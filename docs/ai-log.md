# Журнал работы с ИИ

Что спрашивали у ИИ, что он сделал не так и как это нашли и исправили. Только реальные случаи — из этого журнала собирается раздел README.

| Дата | Инструмент / модель | Запрос (кратко) | Что пошло не так | Как нашли | Как исправили |
|---|---|---|---|---|---|
| 07.11.2026 | Claude Opus 5.5 | «Модель записи времени для SQLite через SQLAlchemy» | Стандартный `DateTime(timezone=True)`: SQLite не хранит пояс — время «12:00 по Минску (UTC+3)» сохранилось как «12:00» без пояса и без перевода в UTC. Отчёт тихо сместился бы на 3 часа | Тест `test_time_is_read_back_in_utc_with_timezone` упал: из базы вернулось время без пояса | Свой тип колонки `UTCDateTime`: при записи переводит в UTC, при чтении ставит метку UTC; время без пояса отказывается записывать (тест `test_time_without_timezone_is_rejected`) |
| 07.11.2026 | Claude Opus 5.5 | «Тест на отказ от времени без пояса» | Тест ловил любое `Exception` — прошёл бы и от совсем другой ошибки | Ревью перед коммитом | Уточнил: ждём `StatementError` с нашим `ValueError` внутри |
| 07.11.2026 | Claude Opus 5.5 | «Подключить приложение к временной базе в тестах» | Тесты подменяли базу для данных, но шаг запуска приложения (создание таблиц) шёл в рабочую базу — в папке проекта появлялся `timetracker.db` | После ручного запуска сервера увидел файл базы в проекте; воспроизвёл одним прогоном тестов | Тесты задают временный `DATABASE_URL` до импорта приложения; добавлены проверки `tests/test_isolation.py` (до исправления обе падали) |
| 07.11.2026 | Claude Opus 5.5 | «Страница интерфейса на чистом JavaScript» | В комментарии внутри скрипта был пример `<script>…</script>`. Браузер принял `</script>` из комментария за конец скрипта — весь код ниже не выполнялся, кнопки не работали, ошибок в консоли не было | Тесты API прошли, но прогон страницы в настоящем браузере (Playwright): после «Добавить сотрудника» сервер не получил ни одного запроса к API | Комментарий переписан; тест `test_page_is_served_and_script_is_not_cut` (с возвращённой ошибкой падает) |
| 07.11.2026 | Claude Opus 5.5 | «Проверить тесты поломками» | Две из пяти поломок тесты «не поймали» — но это была ошибка постановки опыта: защита от второго таймера двойная (код + индекс базы), ломалась только половина | Разбор результатов | Сломал обе защиты сразу — тест упал. Вывод записан: проверять защиту целиком |
| 07.11.2026 | Claude Opus 5.5 | «Проверка, что тесты не трогают рабочую базу» | Моя же проверка требовала «в папке проекта нет файла базы». При обычном запуске приложение и должно его создать — проверка упала на НАСТОЯЩЕЙ базе владельца (2 сотрудника). Удаление «по совету теста» уничтожило бы данные | Перед удалением посмотрел время создания и содержимое файла | Проверка переписана: тесты подключены к файлу вне папки проекта. База владельца не тронута (sha256 до и после совпали) |
| 07.11.2026 | Claude Opus 5.5 | «Переключение работа → перерыв одним действием» | Комментарий в коде объяснял `db.flush()` неверной причиной («без него индекс увидит две открытые записи») | Поломка-проверка: убрал flush — тесты прошли; лог SQL показал, что SQLAlchemy сам пишет UPDATE раньше INSERT | flush оставлен для независимости от внутреннего порядка библиотеки, комментарий исправлен честно |
| 07.11.2026 | Claude Opus 5.5 | «Отчёт с перерывами» | Перерыв в 2 секунды показывался как «перерывы 0 мин» — читается как «перерыва не было» | Снимок экрана в браузере | Меньше минуты показывается словами «меньше минуты» |
| 07.11.2026 | Claude Opus 5.5 | «Кнопки перерыва и обеда на странице» | Большие часы показывали длительность текущего отрезка: после обеда начинали с нуля.
