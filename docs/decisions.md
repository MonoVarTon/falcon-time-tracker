# Решения и почему

| # | Решение | Почему |
|---|---|---|
| 1 | Python + FastAPI | один язык для сервера и тестов; встроенная документация API на `/docs` |
| 2 | SQLite через SQLAlchemy | база в одном файле, не нужно ставить сервер БД; данные переживают перезапуск |
| 3 | Интерфейс — одна HTML-страница с небольшим JavaScript, без сборщика | меньше частей — проще запустить и объяснить |
| 4 | Логика в `services.py`, маршруты в `main.py` только вызывают её | логику можно проверить тестами без HTTP и объяснить отдельно |
| 5 | Время хранится в UTC | нет путаницы с часовыми поясами; показываем в местном времени на странице |
| 6 | Свой тип колонки `UTCDateTime` | SQLite не хранит часовой пояс; без перевода в UTC отчёт сдвигается (найдено тестом, см. `ai-log.md`) |
| 7 | Время без часового пояса — ошибка, а не «угадывание» | «12:00» без пояса неоднозначно; лучше упасть сразу, чем исказить отчёт |
| 8 | Частичный уникальный индекс: один активный таймер на сотрудника | защита в самой базе — даже если два запроса «старт» придут одновременно, второй не пройдёт |
| 9 | `PRAGMA foreign_keys=ON` на каждом соединении | SQLite по умолчанию не проверяет внешние ключи; проверено: без него запись для несуществующего сотрудника проходит |
| 10 | Имена сотрудников не уникальны | в компании бывают тёзки; различаем по id |
